Template Floor Check

OSS Scanner's threat-model template gives one worked example of a severity rubric. In Anthropic's own published ledger, most maintainers rate those bug classes below the floor that example states.

Not affiliated with Anthropic, not reviewed by them. Every figure is recomputed from the public ledger at red.anthropic.com/2026/cvd, snapshot r35. The ten figures Anthropic states in prose reproduce exactly from that file before anything below departs from them.

The example

templates/threat_model.md in anthropics/oss-scanner offers one worked example under the heading How you rate severity:

any buffer overflow, use-after-free, or double free is high+ at a minimum templates/threat_model.md — the only severity guidance a maintainer sees before writing their own

What the ledger shows

In the revealed portion of the ledger,   carry both a Claude severity and a maintainer severity in exactly those classes. Each finding is counted once: a finding can appear under a CVE and several GHSAs at the same time, which double-counts if you iterate advisory records.

The more interesting half

These conventions genuinely differ between projects, and a worked example cannot be neutral between them. Three large C and C++ projects rate memory-safety findings at medium as a matter of course; the kernel, nginx and OpenSSL do not.

What would make this wrong

  • Small and concentrated.  
  • Self-selected. A maintainer severity exists only where a maintainer published an advisory, and that subset runs about 0.24 bands hotter than findings without one. It is not a random sample of the corpus.
  • Possibly the instrument, not the judgement. Maintainers commonly score with CVSS while a rubric need not. This data cannot separate a scoring-framework difference from a disagreement.
  • Ordinal bands. Counts above and below one threshold are reported rather than averaged distances, because CVSS band widths are not equal.
  • It may be deliberate. If the example states a floor the pipeline should apply whatever maintainers do, this is simply the size of that intended gap.

Reproducing it

python3 src/fetch.py                                # pin and hash a snapshot
python3 -I src/template_check.py data/payload-r35.json

Standard library only, no dependencies, offline after the fetch. The same repository holds the full audit, including two errors of its own found and corrected the same way: a breakdown that double-counted advisory records, and intervals that assumed findings were independent when 44.2% of the paired set shares a single discovery date.
